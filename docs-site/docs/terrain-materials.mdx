# Terrain Materials

Most editors let a brush write straight to the terrain chunk: paint an alpha map, edit a heightmap.
WorldMapStudio doesn't. Chunk data is output, rebuilt from scene entities and catalog entries whenever
terrain needs to show or export.

That indirection is what keeps terrain non-destructive. Moving a stamp moves the hill it made. Editing
a road reshapes the ground under it. Changing a material rebuilds every chunk that used it, without
touching the entities that authored it.

## One edit, walked through

A stamp that makes a dirt mound doesn't say "write dirt alpha into slot 2, raise these vertices by 4."
It says two things:

1. It has a shape in the world: center, radius, falloff, strength.
2. It writes that shape into a named grayscale mask.

A material bind component on the same entity says which material goes on which layer.

The mask only exists for the current rebuild. White means the stamp is strong there, black means it's
absent, values between are falloff. The material decides what the mask means: one might read it as
texture coverage and paint dirt, another as a height offset that raises the ground, a third as both.

Scene entities describe where influence exists. Materials describe what that influence does.

## The five primitives

### Deformers

A deformer is any entity that can influence terrain:

- **Landscape Stamp**: a circular influence with radius and falloff.
- **Drawing Target**: a paintable rectangle projected into the world.
- **Landscape Material Bind**: layer/material pairs claimed over the entity's bounds.
- **Procedural Mesh** bound to the built-in `Road` function: a vertex/edge network splined into centre
  and shoulder masks (see [Roads](#roads)). It pairs with a Landscape Material Bind like any other
  deformer.

A deformer can claim layers and materials, write a shape into masks, or both. The contract is
`ILandscapeDeformer`.

### Masks

A grid of values from 0 to 1 describing how much an authored shape affects each point. A stamp writes
a radial mask, a painted drawing target writes a brush mask, a road writes a centre mask and a shoulder
mask. Masks aren't final terrain, they're evidence a function reads later.

### Channels

A channel is a named slot for one kind of mask (`LandscapeChannel`). Its catalog entry sets a name,
a texel resolution per chunk, and a storage bit depth. The entry is persistent; the pixels aren't,
they're scratch data rebuilt on every pass.

Example channel names: `road_mask`, `hill_mask`, `paint_mask`. Stamps and drawing targets pick which
channel to write; materials pick which to read. The name is the handshake between them.

During a build, `LandscapeChannelPool` allocates float buffers for the channels a block needs, plus its
halo. Deformers write into them, functions sample them. Buffers are sampled in world space, so
adjacent chunks agree at shared edges.

### Layers

A layer is a named responsibility plus ordering, like a slot in the project's terrain logic: ground
base, road bed, road surface, cliff detail, painted highlight. What it actually does depends on the
material bound to it in a given chunk.

Fields:

- `IsBase`: the opaque bottom layer, writes no alpha.
- `Priority`: higher wins when the texture budget overflows.
- `DrawOrder`: compositing and height-evaluation order. Must be unique, since the resolver uses it to
  decide whether adjacent layers sharing a material can merge into one texture slot.

### Materials

A material is the behavior assigned to a layer claim. Beyond a texture, `LandscapeMaterial` can carry:

- `TexturePath`: the image for a texture slot.
- `AlphaFunction` / `AlphaParameters`: how to compute texture coverage.
- `HeightFunction` / `HeightParameters`: how to change the heightmap.

`PaintsTexture` is true when it has a texture path or alpha function; `DeformsHeight` is true when it
has a height function. A material can be texture-only, height-only, or both; the builder flags it if a
chunk needs the half it doesn't have.

Examples: grass (texture only), dirt (texture + alpha function), hill (height function only), road
(gravel texture, alpha function, flatten height function).

### Functions

Code that turns channel data into output: an alpha function fills a texture slot's coverage, a height
function rewrites the heightmap. Functions are reusable and don't know their caller. The built-in
`Channel Mask` alpha function doesn't care whether it's dirt, moss, road, or snow, the material tells
it which channel to read and what threshold and softness to use.

## Putting it together

The same stamp example with real names:

1. `Landscape Stamp` writes a radial mask.
2. It writes that mask into a `LandscapeChannel`, say `hill_mask`.
3. `Landscape Material Bind` claims a `LandscapeLayer`, say `small_hill`.
4. It binds a `LandscapeMaterial`, say `soft_dirt_mound`, to that layer.
5. The material's alpha function reads `hill_mask` and produces dirt coverage.
6. Its height function reads `hill_mask` and raises the heightmap.

This split is what lets the same stamp drive different materials, the same material serve stamps,
drawing targets, or roads, and the same channel feed both alpha and height behavior.

## Roads

A road is a Procedural Mesh bound to the built-in `Road` function. It's authored as a vertex/edge
network in the viewport, with the same tool used for procedural meshes: select, marquee, `G`/`R`/`S`
move/rotate/scale, `E` extrude, `F` connect, `Ctrl+S` split, `M` merge, `Ctrl`+click to add. The
network is a graph, not a single path, so it can branch, fork, and close into loops.

Roads are authored flat: a vertex's stored position only matters in X/Z. Placing a vertex drops it onto
the terrain under the cursor, and vertices render projected onto the terrain, but no height is stored.
That's what lets a road follow terrain changes without needing its own height data to stay in sync.

At build time, the network splits into chains (runs of edges between junctions) and each chain becomes
a centripetal Catmull-Rom spline. Coverage at any point comes from the nearest spline segment across
all chains, so forks and crossings blend without special-casing junctions.

A road only picks which channels it writes: a centre channel (full width the centre texture should
show) and a shoulder channel (centre plus shoulder width, so the shoulder reads as one band instead of
a ring with a seam). Turning those into terrain is a Landscape Material Bind's job: bind one
layer/material to the centre channel and one to the shoulder channel, with the centre layer's draw
order higher so the shoulder doesn't paint over it.

## Authoring flow

In the **Landscape** window:

1. Create or edit channels on the **Channels** tab.
2. Create layers on the **Layers** tab (base, priority, draw order).
3. Create materials on the **Materials** tab.
4. Bind alpha and height functions to each material.
5. Bind function parameters, especially channels, to channel names.
6. Check the **Problems** tab for catalog errors.

Then, on entities: stamps, drawing targets, and roads pick which channels they write; material binds
add layer/material pairs and set priority.

**Landscape Debug** shows what the builder produced near the camera: height preview, alpha previews per
slot, slot count, and any problems.

## Code model

Anything implementing `ILandscapeDeformer` takes part in a build through two calls:

- `Claim(...)`: cheap, side-effect free. Returns the layer/material claims this entity wants.
- `Rasterize(...)`: writes this entity's contribution into channel buffers after the resolver decides
  what survived.

Paint components can rasterize with no claims; material bind components can claim with no raster
output.

## Claims and resolution

Deformers emit `LandscapeClaimGroup` objects, each with a stable `Key`, a display `Label`, a
`Priority`, one or more `LandscapeClaim` entries, and an optional source entity id for problem
reporting.

Resolution is deterministic and greedy, favoring predictable terrain over an optimal slot packing that
might vary between chunks:

1. Sort claim groups by key.
2. Drop materialless claims and report them.
3. Resolve layer conflicts (higher priority wins).
4. Resolve base conflicts (only one base layer per chunk).
5. Build texture slots in draw order.
6. Add a fallback base material if none was claimed.
7. Merge adjacent surviving alpha layers using the same material.
8. If the texture limit is exceeded, drop the lowest-priority group holding a slot and retry.
9. Keep height claims independent of the texture budget.

The base slot counts against the texture budget; a height-only material costs no slot.

## Build pipeline

`LandscapeBuilder` builds a block of chunks in five stages:

1. Gather deformers touching the block and its halo.
2. Claim and resolve for every chunk in the block plus halo.
3. Rasterize channels for block plus halo.
4. Evaluate height and alpha for interior chunks.
5. Emit `LandscapeChunkOutput`.

Rasterization only writes channels; evaluation only reads them. That split lets the builder rasterize a
whole neighbourhood before anything samples it, and keeps chunk borders continuous since functions
sample by world position.

## Function details

Functions are discovered by reflection at startup. Materials store function ids, not type names, so an
implementation can move as long as its id stays stable.

Rules: functions must be stateless, all input comes from `LandscapeEvalContext`, `Version` should
change when output behavior changes, `MaxSampleRadius` declares how far outside the chunk the function
samples, and channel parameters declare whether they read or write.

Built-ins:

- `builtin.alpha.channel_mask`: reads a channel as coverage, with threshold, softness, invert.
- `builtin.height.channel_offset`: adds a scaled channel value to accumulated height.
- `builtin.height.channel_flatten`: pulls accumulated height toward a target where a channel is set.

Height functions run in draw order and rewrite the height buffer in place, so a flatten function can
run after a hill function and cut a flat bed into it.

## Settings that matter

`LandscapeSettings` belongs to one map:

- `ChunkWorldSize`: world units per chunk.
- `ChunkHeightResolution`: height vertices per chunk edge.
- `HeightVertexLayout`: `Grid` (corners only) or `GridWithCellCentres` (also a vertex at each cell
  centre).
- `ChunkAlphaResolution`: alpha texels per chunk edge.
- `TextureLimit`: texture slots per chunk, including the base.
- `FallbackMaterialId`: base material used when nothing claims one.
- `AlphaNormalized`: whether output alphas should sum to 1.
- `HeightEncoding`, `HeightOffset`, `HeightScale`: export-oriented height representation.

Changing representation settings triggers a rebuild. Lowering the texture limit or changing the
fallback material can force re-resolution, so layers may appear or disappear.

### Cell-centre vertices

Under `GridWithCellCentres`, height, vertex colour, and vertex light functions run twice per chunk:
once over the corner grid, once over the cell-centre grid. A function only asks for world positions
through `WorldAt`, so the same function and material work for both without knowing which one it's
writing. Each cell renders as a four-triangle fan around its centre vertex.

## Common problems

- **Missing base**: no base layer claimed and no fallback material.
- **Layer conflict**: two groups claimed the same layer with different materials; priority decides.
- **Multiple base layers**: more than one claimed; priority decides.
- **Budget overflow**: more texture slots needed than allowed; lower-priority groups dropped.
- **Below base**: a painting layer sorts below the base and is never visible.
- **Missing alpha function**: a non-base slot has nothing deciding where it shows.
- **Missing height function**: a height claim's material has no available height function.
- **Dangling channel binding**: a parameter points at a channel that no longer exists.

When terrain looks wrong, check in order:

1. Is the catalog valid in **Landscape > Problems**?
2. Does the entity have channel, layer, and material bindings?
3. Does the material bind the right alpha or height function?
4. Are the function's channel parameters bound to real channels?
5. Was the claim dropped by a conflict or budget overflow?
6. Does **Landscape Debug** show non-empty output?
